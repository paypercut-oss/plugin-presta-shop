# plugin-presta-shop

Paypercut's **PrestaShop payment module** (PHP). Distributed from the `paypercut-oss` GitHub org. Lets PrestaShop merchants accept card / Google Pay / Apple Pay payments via Paypercut — using either a **hosted checkout** redirect or an **embedded** inline form. The newer of two PrestaShop integrations Paypercut maintains (the legacy `PayPerCut-PrestaShop` repo — that is the literal repo name on GitHub — is to be deprecated per the system docs).

**Audience**: PrestaShop merchants and store integrators wiring Paypercut as a payment gateway.

## Layout

**Single app — PrestaShop PHP plugin.** Not a monorepo. No Composer / npm tooling. CI/CD is a single GitHub Actions workflow that packages a release zip.

## Architecture

- **`paypercut.php`** — Main module class `Paypercut extends PaymentModule`. Owns install/uninstall, hook registration, the `paymentOptions` hook (hosted vs embedded branching), checkout payload construction, status mapping, logging.
- **`config.xml`** — PrestaShop module metadata (`name`, `displayName`, `version`, `tab=payments_gateways`).
- **`classes/`** — Domain models / API client:
  - `PaypercutApi.php` — HTTP client against `https://api.paypercut.io`
  - `PaypercutTransaction.php` — `ps_paypercut_transaction` row model (checkout/payment IDs, status, amount, currency)
  - `PaypercutRefund.php` — `ps_paypercut_refund` rows + totals
  - `PaypercutCustomer.php` — PrestaShop ↔ Paypercut customer ID mapping
  - `PaypercutWebhookLog.php` — `ps_paypercut_webhook_log` for idempotency
- **`controllers/admin/AdminPaypercutController.php`** — Configure screen + `action=refund` endpoint.
- **`controllers/front/`** — `redirect.php` (creates hosted checkout session, redirects), `checkout.php` (AJAX session creator for embedded mode), `validation.php` (return/confirmation handler — creates the PS Order), `webhook.php` (receives Paypercut webhook events).
- **`sql/install.php`, `sql/uninstall.php`** — Creates/removes the four `paypercut_*` tables. Uninstall preserves transaction history (tables are NOT dropped).
- **`views/templates/`** — Smarty templates under `admin/`, `front/`, `hook/` (payment option UI, admin order panel, return page).
- **`translations/`** — 13 language PHP files (BG, CS, DA, DE, EN, ES, FR, HU, IT, NB, PL, RO, SV). Regenerated by `tools/generate_translations.php`.

## Entry points

- `paypercut.php` — module bootstrap, hook handlers (`hookPaymentOptions`, `hookPaymentReturn`, `hookDisplayAdminOrderMainBottom`, `hookDisplayBackOfficeHeader`, multi-shop `hookActionObjectShopAddAfter`, …).
- `config.xml` — what PrestaShop reads when scanning `/modules/paypercut/`.
- `controllers/admin/AdminPaypercutController.php` — configure UI (API key, checkout mode, wallets, webhook creation).
- `controllers/front/{redirect,checkout,validation,webhook}.php` — runtime payment flow.

## Common commands

This module has **no build step and no test suite**. Operations are packaging and install/uninstall via PrestaShop.

```bash
# Package a release zip (mirrors what the GitHub Actions release-zip workflow does on a v* tag)
# Produces dist/paypercut-presta-shop-<version>.zip with module under paypercut/
git tag v1.0.0 && git push --tags   # triggers .github/workflows/release-zip.yml

# Local manual package
rsync -a ./ /tmp/paypercut/ --exclude .git --exclude .github --exclude vendor
(cd /tmp && zip -r paypercut.zip paypercut)

# Install in a PrestaShop store
# 1. Drop the paypercut/ folder into <prestashop>/modules/
# 2. Back office: Modules > Module Manager > search "Paypercut" > Install
# Or via CLI (PS 1.7+):
php bin/console prestashop:module install paypercut
php bin/console prestashop:module uninstall paypercut

# Regenerate translation files after editing $this->l(...) strings
php modules/paypercut/tools/generate_translations.php
```

## Conventions

- **Hooks**: registered in the `Paypercut::HOOKS` constant; install loops `registerHook()` over each. Use `hookXxx()` methods on the main class.
- **Translation strings**: wrap user-facing strings in `$this->l('...')`. Regenerate `translations/<lang>.php` via `tools/generate_translations.php`.
- **SQL**: tables prefixed `ps_paypercut_*` (`_DB_PREFIX_` is applied). Schema lives in `sql/install.php` — no migration framework; for upgrades add an `upgrade/upgrade-x.y.z.php` file (standard PrestaShop convention).
- **Configuration keys**: namespaced `PAYPERCUT_*` via `Configuration::get/updateValue`.
- **Logging**: `$this->logError()` / `$this->logDebug()` gated by `PAYPERCUT_LOGGING`; routes through `PrestaShopLogger`.
- **Currencies**: enforced via `Paypercut::SUPPORTED_CURRENCIES` (BGN, DKK, SEK, NOK, GBP, EUR, USD, CHF, CZK, HUF, PLN, RON).

## Gotchas

- **PrestaShop version compatibility**: `ps_versions_compliancy` min `1.7.7.0`, max `_PS_VERSION_`; README claims **1.7.7+ / 8.x / 9.x**. PHP 7.1+. Test on each major before release. (Autogen docs list `1.7.x` but the code is more permissive — trust the code.)
- **PCI scope**: this plugin is designed to keep the merchant out of PCI scope by **redirecting to Paypercut's hosted checkout** (or rendering Paypercut's embedded iframe). It must never collect raw PAN data itself. Card fields belong to Paypercut — do not add native card form fields here.
- **Embedded mode quirk**: `getEmbeddedPaymentOption()` intentionally avoids `setForm()` (many PS 8.x/9.x themes don't render its DOM) and uses `setAdditionalInformation()` instead.
- **`success_url` vs `return_url`**: hosted mode uses `success_url` + `cancel_url`; embedded/custom modes use `return_url` only — see `buildCheckoutPayload()`.
- **Webhook idempotency**: events are deduped via `ps_paypercut_webhook_log.event_id` (UNIQUE). Don't bypass — payment status updates must be replay-safe.
- **Payment handoff with paycore**: checkout sessions, payment intents, and webhooks all go through `api.paypercut.io` (paycore). The plugin is a **thin adapter** — checkout creation, status, and refunds are paycore-owned. Treat any non-2xx from the API as user-visible and surface it through `logError()`.
- **Uninstall preserves data**: the four `paypercut_*` tables are NOT dropped on uninstall (intentional, for transaction history). Drop manually if needed for a clean re-test.
- **Two-repo situation**: the legacy `PayPerCut-PrestaShop` repo (literal GitHub repo name; under the `paypercut` org) overlaps with this one — per system docs it should be deprecated in favor of this repo.
